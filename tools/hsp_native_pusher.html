HSP Pusher + ミニインタプリタ

入力した内容は、選んでいるワークに自動で保存されます。アクセストークンは全ワーク共通です(書き出しには含まれません)。
⓪ ビルド対象
Webを選ぶと、実行は web.yml、成果物は hsp-web の zip になります。
① GitHub
トークンはこの端末のブラウザ内にだけ保存されます。送信先は api.github.com のみです。
ファイル・ワークフロー・設定をそのまま複製します(コミット履歴と Secrets は複製されません)。複製したあと、新しいワークとして追加できます。
② アプリ設定
背景画像を選ぶとそれを敷き、無ければ背景色で塗ります。上で選んだアイコンがあれば左に置きます。JPEGで保存されます。
Androidのみ。OFFにすると apk だけを作ります(ビルドが速くなり、成果物も小さくなります)。Playストアに出すときはONにしてください。
Androidのみ。アプリが前回落ちたときなどに、次の起動直後に出る確認用ウィンドウです。テスト用のapkはON、Playストアに出すaabはOFFがおすすめです。OFFでも、落ちた記録の収集は続きます。
ONにすると、apkにだけ MANAGE_EXTERNAL_STORAGE が付きます(aabには付きません)。このaabはPlayストアに出せません。sogmake のような、共有フォルダを直接読み書きするアプリ用です。初回起動時に許可の案内が出ます。
③ 広告 (AdMob リワード)
空欄ならGoogleのテストIDで動きます。本番IDで試す前に、自分の端末をテストデバイスに登録してください。
④ ファイル
更新されたzipを受け取ったときは、ここに選んで「反映してビルド」を押します。変更があったファイルだけが送られます。
ZIP内のパスがそのまま assets/ 以下になります (例: gdata/bgm/dan.txt)。「assets/」で始まる場合はその分を除きます。
⑥ 一括反映 (複数のリポジトリへ、同じファイルを)
選んだリポジトリすべてに、同じファイルを反映します(変更があったファイルだけがコミットされます)。ビルドは、変更があったリポジトリで、GitHub 側で自動で始まります。下のチェックを入れると、その結果をここで待って、成果物も取得できます(待たなくても、ビルドは進みます)。
⑤ Web設定 (Webビルドのとき。空欄でOK)
変えると別の保存場所になり、今までのセーブは見えなくなります。
本番広告にするのは、H5広告が承認され、サイトの公開ドメインで確認してからにしてください。
動きが遅いときは、ビルドし直さなくても、ページのURLの後ろに ?step=20000 のように付けて試せます。
