# Web版(公式 hsp3dish.js)ビルド — 第1弾: 保存(bsave/bload)

## 仕組み
hsp/main.hsp →(web_patch.sh で最小の自動調整)→ 公式 hspcmp → main.ax
公式OpenHSP(固定コミット)を、公式の makefile.emscripten で hsp3dish.js / .wasm にビルド(Emscripten 3.1.74 = 公式CIと同じ版)。
公式C++への変更は2か所だけ: makefile の EXPORTED_RUNTIME_METHODS に FS,ENV を足す / sysreq.cpp の getreq に範囲チェックを足す。
保存: 公式の HSP_SYNC_DIR(IDBFS)に乗せる。web/hsp-web-runtime.js が自動保存・.bak退避・復旧・旧localStorageからの移行を行う。

## 使い方(スマホだけ)
1. 新しいプッシャー(hsp_native_pusher_v2.html)を開く。
2. ⓪「ビルド対象」で Web を選ぶ。①のトークン等はそのまま。
3. ④「プロジェクトZIP」に hsp-web-ci.zip を選び「反映してビルド」を押す(初回は web.yml なども反映される)。
4. 成功すると <アプリ名>-web.zip が保存される。失敗したら、画面に出た「失敗ステップ」と「理由」を教えてください。
5. zip を解凍して、サーバーのテスト用フォルダ(例: https://koborisoft.com/sogiii_test/)に中身をそのまま置く。
   - index.html / hsp-web-runtime.js / hsp3dish.js / hsp3dish.wasm / main.ax / assets.* / webconfig.json を同じ場所に。
6. スマホで https://koborisoft.com/sogiii_test/?diag=1 を開く。右上の ⚙ で保存状態とログが見える。「個別ファイル」の一覧では、ファイルごとに 書き出し(そのままのファイルで保存)/ 読み込み(選んだファイルで上書き。元は .bak に退避)ができる。「ファイルを選んで追加」では、選んだファイルを、そのファイル名のままゲームデータフォルダに入れる(複数選択可、同名は上書き)。

## 注意
- 保存先の名前(IndexedDB)は <saveDir> で決まる。変えると別の保存場所になる(config/web.json の saveDir)。
- 同じ koborisoft.com 内の別アプリと保存場所が重ならないよう、既定はパッケージ名から作る。
- 音(MML)は第1弾では鳴らない。広告は出ない(広告なしで先へ進む)。第2弾=MML、第3弾=広告。

## 第2弾: MML音楽(::mmlt::)

公式 hsp3dish.js には MML が無いので、ミニインタプリタと同じ `hsp-synth.js` で曲を合成し、WebAudio で鳴らします。
- ビルド時に main.hsp の `mmload "::mmlt::…"` を自動検出 → 起動時(「準備中」画面)に先に合成します(dan 約0.6秒/btl 約0.8秒 ※PCの計測。スマホは未確認)
- mp3 / wav は従来どおり公式の命令のまま(`mmloadx` などの包みが、MMLの曲だけをJS側へ回します)
- 動作: mmstop=一時停止 / mmplay=続きから / mmload=先頭に戻る / mmvol(-1000〜0)=音量
- 「タップして開始」を押した瞬間に音が有効になります。画面を隠すと止まり、戻ると再開します
- 1フレームの最大ステップの初期値は 200000 にしました(ちらつき対策。`?step=` で試せます)

### 第2弾で「未確認」のもの(実機で要確認)

- スマホでの合成時間(起動が遅くなりすぎないか)
- mp3 / wav の SE・BGM が公式ランタイムで鳴るか(この部分は元から公式の機能)

## 第3弾: 広告(AdSense Ad Placement API / リワード)

ミニインタプリタと同じしくみ(adBreak, type=reward)を、HSPの `devcontrol "AdMob",17/18/16` につなぎました。
- 設定: プッシャーの「⑤ Web設定」に **AdSenseパブリッシャーID(ca-pub-…)** と **テスト/本番** を追加。空欄なら広告なし(ゲームはそのまま進みます)
- 広告が読み込めない(H5未承認・IDなし・通信不可・ブロック)ときは、失敗として扱い、ゲームは止まりません
- URLでの切り分け: `?noad=1`(広告を無効) / `?adtest=1`(テスト広告) / `?adtest=0`(本番) / `?adid=ca-pub-…`(IDを一時的に差し替え) / `?diag=1`(⚙のログに `[広告]` が出ます)

### 第3弾で「未確認」のもの

## 戻るボタン (getreq SYSREQ_BACKBUTTON = 1004)
スクリプトが `getreq v, SYSREQ_BACKBUTTON` を一度でも読むと、ブラウザの「戻る」操作と Escape キーが「ゲーム内の通知(1)」になります(読むと消えます)。
読まないスクリプトでは、戻るは今までどおりページを戻ります。有効中は、戻るを押してもページを離れません(離れたいときはタブを閉じる/ホームへ)。
未確認: 実機(Chrome)での戻るボタン/ジェスチャーの反応、公式C++への追加パッチ(sysreq.cpp)が実ビルドで通ること。

## mp3 / wav の一時停止・再開
- **mp3(BGM)**: `mmstop`=一時停止(位置を保存) / `mmplay`=続きから / `mmload` し直すと先頭から(MMLと同じ動き)。公式C++の mmman.cpp に最小パッチ(tools/web_patch_sound.py)
- **広告表示中**: 鳴っている音(mp3・wav)を全部一時停止し、広告が終わったら続きから再開(devcontrol "snd_adpause"/"snd_adresume")
- wav の効果音は、`mmstop` では従来どおり止まります(短い音のため)。広告中だけ一時停止します
- 未確認: 実際のエミュレータビルドでパッチが通ること / 実機での動作 / mp3以外(ogg等)

## ゲームパッド (段階2)
- `config/gamepad.json` があると、ビルド時に `webconfig.json` の `gamepad` に入り、`web/pad-engine.js` が Gamepad API のボタンを「割り当てた HSP キーコードのキーボードイベント」に変換して流します(公式C++は無改造)。
- indexMap(物理ボタン番号)があればそれを使い、無ければ標準の並びです。スティックは使いません。画面を離れたときは押しっぱなしを自動で離します。
- ビルドのログ/注釈に「ゲームパッド設定 (Web)」として割り当て結果が出ます。

## セーブデータのバックアップ画面(ユーザー向け) — devcontrol "backup::…"

Android版と同じ書式・同じ規則(詳細は native 側 README を参照)。
```
slotmax=20
devcontrol "backup::sog3sd*.dat::", slotmax[, size]
```
- ゲームを一時停止して画面(`hsp-web-runtime.js`)を出す。`*` = スロット番号(ゼロ埋めなし、`0`〜`slotmax-1`)。パターンに合うスロット以外は、一覧にも出ず読み書きもできない。`.bak` は対象外。
- 取り込みは「スロットを選ぶ」方式(ファイル名は問わない)。元の内容は `.bak` に退避され、**IndexedDBへの保存を確認してから自動で再読み込み**する。保存を確認できなかったときは再読み込みせず、メッセージを出す(取り込んだ内容を失わないため)。
- `web_patch.sh` が `devcontrol "backup::` を `backupshowweb`(`web_compat.hsp`)に置き換える。閉じるまで待ち、その間、MMLと公式側の音も一時停止する。
- 画面が開いている間、ブラウザの「戻る」/ Escape は、ゲームへの「戻る」ではなく画面を閉じる操作になる。
- 診断パネル(`?diag=1`)の従来のバックアップ機能は、そのまま残る(デバッグ用)。
